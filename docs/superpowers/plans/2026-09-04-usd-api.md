# USD Transactions API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add authenticated CRUD endpoints for USD expense movements and USD-category listing at `/api/v1/usd`, using the existing JWT and persistent `mntr_*` token.

**Architecture:** Add `usd_api` as a child blueprint of `api_v1`, so Flask composes the URL to `/api/v1/usd` and preserves the existing parent registration, CORS, and CSRF exemption. The new package owns only USD serialization and validation, and every query is scoped by `get_current_api_user()`.

**Tech Stack:** Python 3, Flask 3.0, Flask-SQLAlchemy 3.1, Flask-JWT-Extended 4.6, SQLAlchemy, pytest.

**Spec:** `docs/superpowers/specs/2026-09-04-usd-api-design.md`

## Global Constraints

- Preserve all URLs, payloads, and behavior of `/api/v1/transactions`.
- Reuse `api_login_required` and `get_current_api_user`. Do not create a USD token, authentication route, CORS rule, or CSRF exemption.
- Implement only `/api/v1/usd/transactions` and `/api/v1/usd/categories`; do not add USD income, budgets, recurrence, savings, web routes, or migrations.
- Every USD response has fixed `type: "expense"` and `currency: "USD"` values.
- A `UsdTransaction` must retain a non-null `category_id` owned by the token user.
- Parse `amount` as `Decimal`, accepting only positive values with at most two fractional digits and at most `9999999999.99`.

```python
def usd_category_schema(category):
    return {'id': category.id, 'name': category.name, 'color': category.color,
            'is_demo': category.is_demo}


def usd_transaction_schema(transaction):
    return {'id': transaction.id, 'type': 'expense', 'currency': 'USD',
            'amount': float(transaction.amount), 'description': transaction.description or '',
            'date': transaction.date.isoformat(), 'category_id': transaction.category_id,
            'category_name': transaction.category.name, 'is_demo': transaction.is_demo,
            'created_at': transaction.created_at.isoformat() if transaction.created_at else None}
```

- [ ] **Step 3: Implement strict validators and the four CRUD views**

```python
from datetime import date as date_type
from decimal import Decimal, InvalidOperation

MAX_USD_AMOUNT = Decimal('9999999999.99')


def _parse_amount(value):
    try:
        amount = Decimal(str(value))
    except (InvalidOperation, TypeError, ValueError):
        return None
    if not amount.is_finite() or amount <= 0 or amount > MAX_USD_AMOUNT:
        return None
    return amount if amount.as_tuple().exponent >= -2 else None


def _parse_date(value):
    try:
        return date_type.fromisoformat(value)
    except (TypeError, ValueError):
        return None


def _owned_category(user_id, category_id):
    return UsdCategory.query.filter_by(id=category_id, user_id=user_id).first()


def _owned_transaction(user_id, tx_id):
    return UsdTransaction.query.filter_by(id=tx_id, user_id=user_id).first()
```

Import `request`, `jsonify`, `extract`, the package/API modules, and USD models.
Decorate every view with `@api_login_required`. For `GET`, apply optional
`year`, `month`, and `category_id` filters using `extract`; order by
`date.desc(), id.desc()` and return `{'transactions': [...], 'total': N}`.
For `POST`, require a JSON object plus `amount`, `date`, and `category_id`;
check that description is a string of length at most 200 and set `is_demo=False`.
For `PUT`, accept a valid subset of those fields but reject a null or foreign
category. For `DELETE`, delete only the owned row. Return `400` for invalid
input, `404 {'error': 'Transacción no encontrada'}` for non-owned rows, and
`200 {'message': 'Eliminada'}` after deletion.
